# Plan de implementación — Lanzador de anuncios con IA

Fecha: 2026-11-16. Fuentes: `01-PRD.md`, `02-TRD.md`, `03-app-flow.md`, `04-UI-UX-brief.md`, `05-backend-schema.md`. Las decisiones tomadas están en `01-PRD.md` § Decisiones aceptadas. Si dos docs se contradicen en nombres de ruta, límites o contratos, manda el TRD (y el schema para tablas). Lo que sigue abierto está al final, en "Huecos detectados".

## 0. Reglas del plan

| Tema | Regla |
|---|---|
| Tamaño | Cada tarea cambia ≤ ~300 líneas escritas a mano. No cuentan: SQL generado por drizzle-kit, `package-lock.json`, fixtures JSON copiados de Meta. |
| Test primero | El criterio "Hecho cuando" es un test o comando concreto. Se escribe el test antes que el código; la tarea termina cuando pasa junto con `npm run lint && npm run typecheck`. |
| Commit | Un commit por tarea, Conventional Commits (`feat(api): magic link`), lint y tests antes de cada commit. Si una tarea queda a medias: `.claude/handoff/<nn>-<tarea>.md`. |
| Modelo | **opus**: seguridad (auth, sesiones, CSRF, cifrado, firmas, SSRF), tenancy, capa de escritura de Meta, Workflows y jobs. **sonnet**: endpoints comunes y UI. **haiku**: cambios mecánicos (config, fixtures, páginas estáticas, revisiones de versiones). |
| Paralelo | La columna "∥ con" lista tareas que pueden correr al mismo tiempo una vez cumplidas las dependencias. Lo que no figura ahí va en serie. Las migraciones (5 → 6 → 7) van siempre en serie para no chocar la numeración. |
| Bindings | Cada binding de `wrangler.jsonc` lo agrega la tarea que lo usa primero (D1 en 5, `RL_*` en 10, `AI` en 66, `JOB_WF` en 48, `LAUNCH_WF`/`LAUNCH_ITEM_WF` en 49–50). Así un deploy nunca apunta a un recurso que todavía no existe. |
| Fakes | Todo proveedor externo se prueba con MSW (`tests/helpers/msw/*`) dentro de `@cloudflare/vitest-pool-workers`. Workers AI se prueba con un `AiProvider` falso (`tests/helpers/fake-ai-provider.ts`) y un binding `AI` simulado. Ningún test de CI llama a Meta, Resend, Workers AI ni Google reales. |
| Arneses que crecen | Toda tarea que agrega una ruta bajo `/api/w/:wid/*` suma su fila en `tests/integration/roles.matrix.ts` y, si tiene parámetro de id, en `tests/integration/tenancy.params.ts`. Los tests de la tarea 14 fallan si una ruta registrada no tiene fila. |
| Cuotas | Respetar TRD §4.4 (polling) y §10 (plan Free): sin polling fuera de lo listado, ≤ 45 subrequests por instancia de Workflow, streams para archivos, sin `COUNT(*)` por request, sin KV. **Sin pruebas de carga contra remoto**: k6 solo contra `wrangler dev`. Los E2E contra el preview son cortos (un flujo por hito). |
| Plata y borrados | Preguntar antes de: comprar dominio para Resend, cargar un medio de pago en Cloudflare o en cualquier proveedor, borrar recursos remotos, deploy a producción. |
| Dev local | `npm run dev` = Vite (5173) con proxy de `/api` a `wrangler dev` (8787); `.dev.vars` con `APP_ORIGIN=http://localhost:5173`. El E2E local corre `wrangler dev --var APP_ORIGIN:http://localhost:8787` sobre el build. Se usa Chromium (acepta cookies `Secure`/`__Host-` en `localhost`). |
